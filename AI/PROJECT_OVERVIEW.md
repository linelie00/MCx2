# PROJECT_OVERVIEW.md

## 프로젝트 이름

미하티 웹페이지

## 한 줄 설명

자캐커플 "미하티"의 세계관, 캐릭터, 이야기, 이미지, 음악을 기록하고 감상할 수 있는 개인 웹 아카이브이다.

## 프로젝트 목적

이 프로젝트는 단순한 캐릭터 소개 페이지가 아니라, 미하티라는 자캐커플의 분위기와 서사를 하나의 기록 보관소처럼 보여주는 웹페이지를 목표로 한다.

사용자는 Home, World, Character, Story, Gallery, Playlist 페이지를 통해 캐릭터의 관계성, 세계관, 이야기, 이미지, 음악을 차분하게 감상할 수 있다.

## 핵심 분위기

전체 분위기는 다음 키워드를 중심으로 한다.

- 양피지
- 낡은 책
- 기록 보관소
- 차분한 중세풍
- 캐릭터 고유 색상
- 오래된 문서
- 조용한 서사
- 개인 아카이브

## 주요 페이지

### Home

프로젝트의 첫인상을 전달하는 메인 페이지이다.

역할:

- 미하티 소개
- 전체 분위기 전달
- 각 페이지로 이동하는 허브
- 대표 문구 또는 상징 이미지 표시

개선 방향:

- 첫 화면에서 세계관의 감성이 느껴지도록 구성한다.
- 단순 메뉴 나열보다는 책의 목차나 기록 보관소 입구 같은 느낌을 준다.
- World / Character / Story / Gallery / Playlist로 자연스럽게 이동할 수 있게 한다.

---

### World

미하티가 존재하는 세계관을 소개하는 페이지이다.

역할:

- 세계관 설명
- 배경 설정
- 지역, 시대, 분위기, 규칙 소개
- 필요한 경우 연표나 설정집 형태로 구성

개선 방향:

- 설명문을 너무 길게 나열하지 않는다.
- 섹션을 나누어 낡은 문서, 기록, 장서 같은 느낌을 준다.
- 설정이 많아질 경우 카드형 또는 아코디언 형태로 정리한다.

---

### Character

미하티 캐릭터를 소개하는 페이지이다.

역할:

- 캐릭터 프로필 표시
- 캐릭터 고유 색상 표시
- 성격, 상징, 관계성, 문구 정리
- 캐릭터 간 대비와 연결성 표현

개선 방향:

- 캐릭터별 고유 색상을 사용하되 전체 중세풍 톤과 충돌하지 않게 한다.
- 프로필 카드, 인용구, 관계 설명을 분리한다.
- 캐릭터 정보는 JS 데이터 파일에서 관리한다.

---

### Story

미하티의 이야기를 정리하는 페이지이다.

역할:

- 에피소드 목록
- 장면별 이야기
- 시간순 또는 주제별 이야기 정리
- 주요 사건 기록

개발 방향:

- 긴 글을 한 번에 보여주기보다 읽기 좋은 단위로 나눈다.
- 낡은 책의 장, 기록 문서, 일지 같은 구성을 고려한다.
- Story 데이터는 로컬 JS 파일로 관리한다.

---

### Gallery

미하티 관련 이미지를 감상하는 페이지이다.

역할:

- 이미지 목록 표시
- 이미지 확대 보기
- 이미지별 제목, 설명, 태그 표시
- 캐릭터별 또는 분위기별 필터 제공 가능

개발 방향:

- 이미지 오브젝트를 활용해 관리한다.
- 초기에는 프론트엔드 assets 기반으로 구성한다.
- 이후 필요하면 Express 서버에서 이미지 목록 또는 메타데이터를 제공한다.

---

### Playlist

미하티와 어울리는 음악을 모아두는 페이지이다.

역할:

- 곡 목록 표시
- 곡 설명 표시
- YouTube API 연동
- 플레이리스트 유지
- 음악을 통해 캐릭터와 스토리 분위기 전달

개발 방향:

- 초기 UI는 로컬 데이터 기반으로 먼저 만든다.
- 이후 Express 서버를 통해 YouTube API를 연동한다.
- API Key는 서버 환경변수에서 관리한다.
- 플레이리스트 정보 저장 기능은 백엔드에서 최소한으로 처리한다.

## 사용자 경험 목표

사용자가 웹페이지에 들어왔을 때 다음 느낌을 받을 수 있어야 한다.

- 오래된 책을 펼친 듯한 느낌
- 캐릭터 기록을 열람하는 느낌
- 조용하고 차분한 중세 세계에 들어온 느낌
- 캐릭터와 스토리를 천천히 감상하는 느낌
- 개인적인 창작 아카이브를 둘러보는 느낌

## 콘텐츠 관리 방식

Character, World, Story 데이터는 DB에 저장하지 않고 프론트엔드의 JS 데이터 파일로 관리한다.

이유:

- 데이터가 자주 추가되지 않는다.
- 개인 프로젝트이므로 관리 비용을 줄이는 것이 좋다.
- 프론트엔드 UI 개발 속도를 높일 수 있다.
- 불필요한 백엔드 복잡도를 줄일 수 있다.

예상 데이터 파일:

```txt
client/src/data/
  characters.js
  world.js
  stories.js
  gallery.js
  playlist.js
```

## 백엔드 사용 범위

Express 백엔드는 다음 기능을 위해 사용한다.

- 이미지 관리
- Playlist 정보 저장
- YouTube API 호출
- 필요한 경우 프론트엔드에 데이터 제공

초기에는 프론트엔드 완성도를 우선하며, 백엔드는 나중에 연결한다.
